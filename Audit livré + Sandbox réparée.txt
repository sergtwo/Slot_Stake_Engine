Roadmap — Simulation sérieuse de Fury of Anubis
0. Ce qu'est vraiment Fury of Anubis (rappel technique)

C'est un cluster/pay-anywhere tumble dans la famille de Sweet Bonanza / Gates of Olympus, pas une slot à lignes classiques :

    Grille 6×5, gain dès 8 symboles identiques n'importe où sur la grille.
    Tumble/cascade : les symboles gagnants disparaissent, de nouveaux tombent du haut, on ré-évalue, on recommence tant qu'il y a un gain.
    Multiplicateurs "Wrath" : des symboles multiplicateur (2× à 500×) apparaissent, s'accumulent dans un pool pendant toute la séquence de tumble, et s'appliquent à la somme totale gagnée au moment où la séquence se termine.
    Scatter Anubis : 4+ scatters → Free Spins (généralement 15 spins).
    En Free Spins : les multiplicateurs deviennent sticky (ils restent en jeu) et le pool ne se remet pas à zéro entre les tumbles.
    Bonus Buy : ~100× la mise pour déclencher directement les FS, ~200× pour une variante super.
    RTP cible : 96.5% (version standard), variance très haute, max win ≈ 5000×.

Rien de tout ça n'existe dans la sandbox actuelle. La sandbox actuelle est un tirage random + comptage naïf, sans tumble, sans reel spin, sans multiplicateur sticky, sans free spin, sans bonus buy, sans RTP contrôlé.

2. Plan de travail structuré (5 phases)
Phase 1 — Fondations math (1 semaine)

Objectif : Le serveur produit des payloads Pragmatic-compatibles avec une math cluster+tumble+multiplicateurs sur RTP mesuré.

Livrables :

    sandbox-server/ (nouveau) : Express Node.js, endpoints doInit, doSpin, doCollect.
    games/vs20wraanu/config.json : reel strips + paytable + weights (extraits ou reconstruits depuis les JSON Pragmatic déjà dans le repo).
    engine/cluster.ts : évaluateur cluster (retourne positions gagnantes).
    engine/tumble.ts : séquenceur de tumble complet.
    engine/wrath.ts : gestion pool de multiplicateurs.
    engine/rng.ts : RNG seedé (mulberry32 ou équivalent).
    tools/rtp-sim.ts : simulateur qui joue 1M spins et affiche RTP mesuré + stats.

Critère de succès : RTP simulé sur 1M spins = 96.5% ± 0.5%.
Phase 2 — Free Spins & Bonus Buy (3-4 jours)

Objectif : Cycle complet FS + BB.

Livrables :

    State machine FS côté serveur (sticky mult persistant).
    Retrigger (+5 FS si 3+ scatters pendant FS).
    Endpoint doBuyBonus (100× bet → entre en FS immédiatement).
    Payload FS complet dans la réponse (fs=N, wm=X,Y,Z liste de mult sticky, fs_left=N).

Critère de succès : FS trigger rate mesuré ~1/200 spins, RTP FS + base = 96.5%.
Phase 3 — Rendu client sérieux (2 semaines)

Objectif : Le client ressemble à une vraie slot, pas à un mockup.

Livrables :

    SlotEngine refonte : composant Reel autonome par colonne avec scroll animé + easing.
    TumbleController : orchestre explosion → chute → refill.
    WinPresenter : halo + compteur qui monte + big/mega/epic/ultimate.
    WrathBar UI (Svelte) qui écoute les events du moteur.
    AnubisController : states idle/attack/rage.
    SoundManager avec Howler.js (sons déjà extraits dans extracted_fury_of_anubis/).
    PaytableModal, BuyBonusModal, AutoplayPanel.

Critère de succès : side-by-side avec une vidéo YouTube de Fury of Anubis, feeling comparable à 70%.
Phase 4 — Free Spins UI & polish (1 semaine)

Livrables :

    Intro screen "You won 15 Free Spins".
    HUD FS avec compteur + pool visible + Anubis rage.
    Outro screen "Total win 250.00 €".

Phase 5 — Généralisation à d'autres slots (1 semaine)

3. Effort total réaliste

    Version jouable "belle" (Phases 1+2+3) : ~3-4 semaines en focused dev solo.
    Version publiable comparable au vrai jeu (Phases 1→4) : ~5-6 semaines.
    Framework généralisé multi-jeux (Phases 1→5) : ~7-8 semaines.
